**回填时发现的两个实质问题（必须记下）**：

**问题一：D-10 只定义了"哪些算中转"，没定义"哪些算推进"。**

EX-02 判定式的第 4 行是"若存在推进事件晚于 `t_hub` → 不命中"。如果"推进事件"只包含两类中转事件，那么：

```
at_hub（t_hub） → in_transit（在途 3 天） → 无后续事件
```

会因"t_hub 之后无中转事件"被判为**滞留**。而这是**正常的干线运输**。

> **方向性错误**：D-06 说 EX-02 的业务含义是"中转滞留，需要跟进物流推进"。把正常在途判成滞留，是**误报**，且误报方向与业务含义相反。这比"漏报"更伤一线客服的信任。

**问题二：EX-02 采纳选项 A 后，混装了两类业务情形。**

- `at_hub` 后未动 = **站内滞留** → 客服动作是"催站点"；
- `departed_hub` 后未到下一站 = **干线在途滞留** → 客服动作是"查干线"。

两者共用一个异常类型（EX-02）但**处理动作不同**。这不会导致判定错误，但会导致**客服按错误路径处理**。回填时已在 P1-001-01 §4.2 要求证据中标注子情形（`hub_inside` / `in_transit_stuck`）。

> 这一条**不是** D-10 的错误——选项 A 的代价在原表中已写明（"会与干线滞留混在一起"）。回填的职责是**把这个代价转成可执行的要求**，而不是假装它不存在。
