## 2. 两个实验：控制变量分析

### 实验 A：同模型、不同部署（本地 Ollama ↔ 线上 API）

**线上可用性核实（文档级）**：
- **SiliconFlow** 提供 `Qwen/Qwen3-Embedding-0.6B`（1024 维、32K 上下文、OpenAI 兼容 `https://api.siliconflow.cn/v1`，$0.01/1M tokens）——**与本地为同一开源模型名** ✅
- 阿里云百炼 `text-embedding-v4` 标注"属于 Qwen3-Embedding 系列"（¥0.5/1M，兼容 OpenAI 接口），但**不公开是否等同 0.6B 开源权重** → 若使用需按"近同系列、不同权重"处理 ⚠️

| 可控制 | 无法控制（必须标注的限制） |
|---|---|
| 相同输入语料与查询文本 | **权重精度**：本地 Ollama 为 GGUF 量化版（639MB ≈ Q8_0 量级）；线上大概率为 FP16/BF16 原始权重 |
| 相同评估代码、相似度算法（余弦）、Top-3、指标口径 | **预处理差异**：Qwen3-Embedding 支持 instruction-aware 前缀，双方是否加、加什么，无法从外部确认 |
| 相同向量维度（1024）与相似度归一化 | 分词器版本、推理引擎数值差异 |
| 相同运行环境（本机、网络、时段） | 线上服务的排队/批处理策略 |

**结论：A 是"同模型名、近同配置"对照，不得宣称完全控制变量实验。**

### 实验 B：不同模型、相同检索任务

- 基线：本地 `qwen3-embedding:0.6b`（实验 A 本地侧）；
- 候选：`text-embedding-3-small`（OpenAI，1536 维、$0.02/1M、8K 上限）；
- 备选候选（若走国内线路）：SiliconFlow 上的 `BAAI/bge-m3`（$0.01/1M、1024 维）。
- 维度不同 → 指标不受影响（各自空间内余弦），但**向量存储与索引配置必须按模型隔离**（见第 6 节）。
- **不预设候选更优**：MTEB 分数（0.6B 64.33 vs 3-small 62.3，不同榜单不可直接比）仅供参考，以本任务测试集实测为准。

## 4. 指标定义与人工核验示例

| 指标 | 公式 | 说明 |
|---|---|---|
| Recall@3 | Σ\|rel∩Top3\| / Σ\|rel\| | 仅非空召回用例 |
| Precision@3 | Σ\|Top3∩(rel∪allow)\| / Σ\|Top3\| | 分母为实际越阈值条数 |
| MRR | (Σ 1/首个rel名次) / 用例数 | 未命中计 0 |
| 无关误召回率 | 越阈值的无关查询数 / 无关查询总数 | 目标 = 0 |
| 首载时间 | 首个请求 wall-time | 含模型加载 |
| 预热延迟 | 同输入重复 ≥20 次：p50 / p95 | 排除首载 |
| 失败率/超时率 | 失败(含超时)请求数 / 总请求数 | 按重试策略（≤2 次）计最终失败 |

**人工核验示例（复现第三阶段 8 个召回用例）**：
rel 命中：Q1✓ Q2✗ Q3a✓ Q3b✓ Q4✗ Q6✗ Q7✓ Q8✓ → Recall = 5/8；
Top 条数：2+1+3+3+0+1+3+1 = 14，其中相关：1+0+1+1+0+0+2+1 = 6 → Precision = 6/14；
MRR：1+0+1+1+0+0+1+1 = 5 → /8 = **0.625** ✅ 与 JSON 报告一致。

## 5. 延迟与成本测量方法

**本地（Ollama）**：
- wall-time：`perf_counter` 包住单请求；
- 服务器内部时间可直接取原生响应字段 `total_duration` / `load_duration`（纳秒）→ **模型计算时间**；
- 网络/协议开销 ≈ wall − total_duration（回环网络，近似为序列化开销）；
- 相似度计算与排序：纯 Python 对 12 条记忆约 <1ms，单独计时报告；
- 完整检索耗时 = 查询嵌入 + 余弦排序（原型已有）。

**线上（API）**：
- wall-time 同法；**无法**从响应拆分服务器计算时间 → 报告 wall p50/p95 并注明含网络 RTT（同机同网同时间段测量以降低方差）；
- Token 用量从响应 `usage.prompt_tokens` 记录。

**成本（文档级定价，2026-06/07 核实）**：
| 服务 | 单价/1M tokens |
|---|---|
| SiliconFlow Qwen3-Embedding-0.6B | $0.01 |
| text-embedding-3-small | $0.02（batch $0.01） |
| 百炼 text-embedding-v4 | ¥0.5（batch ¥0.25） |
| 本地 Ollama | 0（电费/折旧忽略不计） |

**月成本估算（公式+示例，假设须在报告中醒目标注）**：
`月 tokens ≈ 记忆存量×40 + 月写入×40 + 日查询×25×30`
示例（200 条存量、500 次写入/月、200 查询/日）≈ 8k + 20k + 150k = **178k tokens/月 ≈ 0.178M**：
- 3-small ≈ $0.0036/月（约 ¥0.026）；SiliconFlow 0.6B ≈ $0.0018/月；本地 ≈ 0。
- 结论：该量级成本可忽略，选型由质量/隐私/运维决定，而非价格。

## 6. 统一后端接口设计（仅设计）

```
class EmbeddingBackend:                       # 协议
    name: str          # "ollama-local" / "siliconflow" / "openai"
    model_id: str      # 完整模型标识（含版本/tag）
    dim: int           # 由首次探测确定并缓存
    def embed(texts: list[str], timeout: float) -> list[list[float]]

OllamaBackend      -> POST {base}/api/embed            (urllib, 零依赖)
OpenAICompatBackend-> POST {base}/v1/embeddings        (urllib 或项目已装 openai)
```

**接入与验证要点**：
1. 配置：`EMBED_BACKEND / EMBED_BASE_URL / EMBED_MODEL / EMBED_API_KEY(仅环境变量,不落盘不打印)`；
2. **维度探测**：首次 `embed(["dim probe"])` 校验 dim ∈ {1024, 1536, 768…} 并与向量表登记一致，不一致拒绝启动语义层；
3. **索引一致性**：向量表以 `(model_id, dim)` 为命名空间；检索时只读当前 model_id 的向量；换模型 = 重建，旧向量保留可回滚；
4. 错误分类统一：`UNREACHABLE / MODEL_NOT_FOUND / AUTH / RATE_LIMIT / TIMEOUT / HTTP_xxx`（修复 404 分类缺陷）；
5. 评估脚本（原型）最小重构：`--backend` 参数 + 上述协议实现替换 `embed_texts()` 内部——**评估代码与语料完全不变，两侧共用**。

## 7. 安全、隐私与降级

- 测试语料全部虚构；**实验 A/B 中线上侧会把虚构文本（非真实记忆）发送至云端**——生产接入时必须改为"仅本地"或用户显式同意；
- Key 只从环境变量读取，任何日志/报告不落 key；
- 降级链：线上超时/限额/失败 → 重试≤2 → 弃用语义层 → 纯关键词检索（行为=当前 172 测试基线）；
- 评估脚本写入均为新文件（`拒绝覆盖` 保护保留）。
