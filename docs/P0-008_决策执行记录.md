### 7.3 是否避免因时间不同步误报 EX-04

**是，且从"判定式"层面根治**：旧伪码第 2 步是 `updated_at < as_of − W1`（依赖未定值，W1 缺失时整条规则不可执行，只能靠"先跳过"）；新伪码把它拆成"是否存在值差 → 能否确认是延迟 → 否则转待核实"，**W1 不参与任何分支条件**。

**由此得到一个重要结论**：V1 可以在 W1 未定的情况下安全运行——`conflict` 的主判定路径（同批次写入 + 组合非法）不需要 W1；有值差时一律 `pending_verification`。代价是自动化率低、人工核实多，但**不会误报**。

### 7.4 安全降级路径

```
三方取数
 ├─ 任一缺失 ───────────────▶ data_missing        → 声明缺什么，不判异常
 ├─ 有"同步中"信号 ─────────▶ sync_in_progress   → 标注待同步，不判异常
 ├─ 无值差 + 组合合法 ──────▶ 正常
 ├─ 无值差 + 组合非法 ──────▶ conflict → EX-04
 └─ 有值差、无法确认延迟 ───▶ pending_verification → 待核实/人工
```

`pending_verification` 是**强制兜底**：D-08-4 要求"无法确认时进入待核实或人工处理路径"，此处落为显式取值，而非"沉默地判矛盾"或"沉默地放过"。
