## 4. EX-04 状态组合矩阵（摘要）

> 完整版见 P0-004 §3。**枚举为候选集，标"待定义"**——项目内无任何企业状态定义可依据。

### 4.1 枚举规模

订单 8 态 / 物流 10 态 / 售后 8 态。

### 4.2 合法组合 8 条（规则式，非穷举）

L-1 支付前 ｜ L-2 已付待发货 ｜ L-3 运输中 ｜ L-4 签收后（含签收后售后） ｜ L-5 退货退款闭环 ｜ L-6 未发货关闭 ｜ **L-7 仅退款例外** ｜ L-8 物流异常本身合法。

### 4.3 非法组合 6 类（= 矛盾）

| 编号 | 组合 | 含义 |
|---|---|---|
| C-01 | `paid` + `delivered` | 未发货却已签收 |
| C-02 | `delivered/completed` + 未签收物流态 | 订单签收、物流未签收 |
| C-03 | `closed` + 在途/派送 | 已关闭仍在派送 |
| C-04 | `refunded` + `delivered` + `returning`（退货退款类型） | 退货退款但货未退 |
| C-05 | 售后 `refunded` 但订单未反映 | 已退款订单状态未同步 |
| C-06 | `paid` + `delivered` + `returning` | 三方全矛盾 |

### 4.4 三个关键设计判断

1. **缺失 ≠ 矛盾**：实体缺失/字段为 null → `data_missing`；售后 `none` 是**合法状态**不是缺失。任务单明确要求的分流，已在 §3.4 落表。
2. **C-04 存在合法例外**：`refund_only`（仅退款）下 `refunded + delivered` 合法（L-7）。因此矛盾判定**必须**依赖 `after_sale.type`；该字段是否存在属待定义 → 若不存在，C-04/C-05 不可判定。
3. **`unclassified` 必须兜底**：枚举不全时宁可报"未分类→转人工"，不得硬套一个矛盾类型。这是防"模型编造矛盾"的最后一道闸。

### 4.5 时间不同步处理

某字段 `updated_at` 落后 `as_of` 超过 **W1** → 标 `data_stale`，该字段**剔除**出矛盾判定，不判 EX-04。**W1 未定义 → 新增待确认。**
