## 5. 三个新增场景的详细验收内容

### 5.1 SC-044 同步中 `sync_in_progress`

| 项 | 内容 |
|---|---|
| **验收目的** | 证明系统能识别"数据正在同步"这一状态，且**不把它当矛盾**（D-08-3 要求区分"数据同步中"） |
| **输入条件** | 订单/物流/售后三方状态存在值差；同时存在**同步动作进行中的信号**（如上游已变更、下游尚未反映，且有明确的同步批次/同步标记） |
| **预期结果** | ① 归类为 `sync_in_progress`；② **不判 EX-04**；③ 对外提示"数据同步中"而非"状态矛盾"；④ 不进入审批（无需人工审一个"还没同步完"的单） |
| **反例（必须失败）** | 若实现把该场景判为 C-01~C-06 任一矛盾 → 该场景失败 |
| **为什么必须独立成条** | 与 SC-043（`data_stale`，含义是"旧"）语义不同。若共用一条，无法证明实现区分了"旧数据"与"正在更新" |

### 5.2 SC-045 无法判定 `pending_verification`

| 项 | 内容 |
|---|---|
| **验收目的** | 证明在 W1 未定、无法区分"同步延迟"与"真实矛盾"时，系统走**安全降级**而非猜测（D-08-4） |
| **输入条件** | 三方有值差；**既无同步信号**（排除 SC-044）；**也无足够信息确认是延迟**（排除 SC-043） |
| **预期结果** | ① 归类为 `pending_verification`；② **不判 EX-04**；③ 进入待核实/人工处理路径；④ 审计记录"为何转人工"（缺哪个判据）；⑤ 不得静默放过，也不得静默判矛盾 |
| **反例（必须失败）** | 判为 EX-04，或直接返回"正常"而无任何提示 → 该场景失败 |
| **为什么必须独立成条** | 这是 W1 未定期间的**默认支路**。W1 一天不定，这条路径就是最常走的路径；不测等于主干无覆盖 |
| **特殊说明** | 该场景是**唯一**允许"没有确定预期业务结论"的场景——它的正确性体现在"**承认不知道**"，而非"给出答案" |

### 5.3 SC-052 关联异常证据完整保留

| 项 | 内容 |
|---|---|
| **验收目的** | 证明 D-06-2"其他命中异常作为关联异常保留，不得直接丢弃"真的被实现 |
| **输入条件** | 复用 SC-050 的三异常叠加（EX-02 + EX-03 + EX-04 同时成立） |
| **预期结果** | ① `is_primary == true` 的记录**有且仅有 1 条**（EX-04）；② 另 2 条 `is_primary == false`；③ **`len(related_anomaly_ids) + 1 == 3`**；④ 每条关联记录均含 `anomaly_type` 与非空 `evidence`；⑤ 关联记录在响应中**可见**，不得只返回主异常 |
| **反例（必须失败）** | 只返回 1 条异常、或关联记录无 `evidence`、或 `related` 数量不足 2 → 失败 |
| **为什么必须独立成条** | SC-050 只断言了"主异常是 EX-04"，**没有断言其余异常是否还在**。D-06-2 是硬约束，必须单独可证伪 |
